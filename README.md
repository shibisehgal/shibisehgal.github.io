# shibanisehgal.com

Personal website for artist **Shibani Sehgal**. Plain static HTML/CSS served from this
repo's root via GitHub Pages (custom domain in `CNAME`). No framework.

## What's here

| Path | Purpose |
|------|---------|
| `index.html` | Home: hero (artist name), **Latest works** (featured), about |
| `works/index.html` | Full gallery (all works) |
| `style.css` | Butter-yellow theme (Fraunces + Mulish) |
| `nav.js` | Accessible mobile nav toggle |
| Resume | External Google Doc — the "Resume" links point straight to it (edit the doc to update) |
| `static/works/` | Optimized gallery images + `works.json` (generated by the build) |
| `scripts/build-works.mjs` | Reads the Drive folder, optimizes images, bakes the gallery HTML |
| `works.config.json` | `driveFolderId` (the folder the site reads) |
| `works.seed.json` | Local fallback images (used only if Drive can't be read) |
| `works.js` | Legacy live-CSV layer (inert unless `csvUrl` is set) |
| `.github/workflows/build-works.yml` | Scheduled bake + auto-commit |

## How "Latest works" updates

Shibani **drags images into one Google Drive folder** — see **[ADDING_WORKS.md](ADDING_WORKS.md)**.
The GitHub Action runs on a schedule (hourly + manual "Run workflow"), reads the folder via a
read-only **service account**, downloads + optimizes each image into `static/works/`, regenerates
the gallery HTML between the `<!-- WORKS:* -->` / `<!-- LIGHTBOX:* -->` markers, and commits the
result. GitHub Pages then serves it. Metadata comes from each file:

- **caption** = file name; **medium** = after first `|` (or the Drive Description); **date** =
  after second `|` (else the upload date); **featured** = file lives in a `Featured` subfolder.

## One-time setup (already done — for reference)

1. **Service account** (read-only Drive access):
   - Google Cloud Console → new project → enable **Google Drive API** → create a **service
     account** → create a **JSON key**.
   - **Share the Drive folder** with the service account's email (Viewer).
2. **Wire it in:**
   - `driveFolderId` in [`works.config.json`](works.config.json) = the folder's ID (from its URL).
   - Add the JSON key as a GitHub **Actions secret** named `GDRIVE_KEY`:
     `gh secret set GDRIVE_KEY < your-key.json`
3. **Workflow permissions:** repo **Settings → Actions → General → Workflow permissions →
   Read and write** (lets the bake commit images back). The workflow also declares
   `permissions: contents: write`.

> ⚠️ The service-account key file must **never** be committed. `.gitignore` already excludes
> `website-reader-*.json`, `*service-account*.json`, etc.

## Rebuild locally

```bash
npm install                                   # one-time: installs sharp
GDRIVE_KEY="$(cat your-key.json)" npm run build   # reads the Drive folder, bakes the gallery
python3 -m http.server 8000                   # preview at http://localhost:8000
```

Without `GDRIVE_KEY`, the build falls back to `works.seed.json` (the `static/portfolio/`
originals) so it still produces a non-empty gallery.
